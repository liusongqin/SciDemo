# SciDemo Agent 入门介绍：逐页内容与讲解稿

## 讲述目标与制作约定

- 听众：有基础数学知识，但没有编程、人工智能或 Agent 背景的理科学生。
- 篇幅：5 页，约 6–8 分钟；每页只回答一个主要问题。
- 主线：从“面积为 2 的正方形，边长是多少？”出发，依次认识 Agent、求解闭环、四个角色、计算证据和系统架构。
- PPT 屏幕只放关键结论和示意图；详细解释写入每页演讲者备注。
- 本文件先完成内容梳理，再据此制作本地 PPT。原有《SciDemo_Agent平台搭建与演进.pptx》保留。

## 第 1 页｜SciDemo：会使用计算工具的学习助手

### 这一页要回答什么

Agent 是什么？这个项目能帮学生做什么？

### 屏幕文字

**主标题：SciDemo：会使用计算工具的学习助手**

引入问题：

> 面积为 2 的正方形，边长是多少？请说明怎么算、怎么检查。

图中标注：正方形面积 `2`；边长 `x`；因此 `x² = 2，x > 0`。

一句话定义：

> Agent 是能围绕目标选择工具、读取结果，再决定下一步的 AI 助手。

系统帮助学生看到：**计算结果 · 检查依据 · 解题说明**。

### 建议讲解稿

先从一个大家都认识的问题出发：一个正方形的面积是 2，它的边长是多少？我们不仅想得到一个数字，还想知道怎么计算、这个数字为什么值得相信。SciDemo 就是用来展示这一过程的教学系统。这里的 Agent，可以先理解成一位会使用计算工具的学习助手。它读懂目标后，会选择合适的工具，看工具返回了什么，再决定是继续计算、修改方法，还是整理答案。它的能力来自语言模型、计算工具和流程控制的配合。

### 画面安排

左侧为学生的问题卡片与一句话定义，右侧为面积等于 2 的正方形；底部用三个短标签呈现“计算结果、检查依据、解题说明”。

### 学生带走的一句话

**Agent 会组织行动，用工具和结果推进解题。**

## 第 2 页｜它怎么工作：想办法 → 动手算 → 检查 → 再决定

### 这一页要回答什么

为什么它可以根据计算结果继续行动？

### 屏幕文字

**主标题：一次求解，是一个反馈循环**

四步流程：

1. **理解目标**：题目给了什么？最后要得到什么？
2. **选择工具**：求根、求导、积分，还是画图？
3. **执行计算**：由受控的科学计算程序得到结果。
4. **检查后决定**：结果是否可靠？还有什么需要做？

反馈箭头：**检查未通过 → 调整方法或参数，再尝试**。

出口：**可以汇总时 → 整理说明与证据**。

底部说明：**语言模型负责理解与选择；计算工具负责实际运算。**

小字：尝试有次数和时间限制，必要时可由人确认。

### 建议讲解稿

可以把这个过程类比为做实验：先明确要研究什么，再选择方法，动手取得结果，然后根据证据决定下一步。在 SciDemo 里，语言模型负责理解问题和选择动作；真正的数值或符号计算，由科学计算程序完成。工具返回结果后，系统进行检查，把结果和检查记录交给下一轮决策。如果当前步骤未通过检查，就可能修改方法或参数；如果还需要更多计算，也可以继续调用工具。这就形成了反馈循环。系统并不会无限尝试，有步数、重试和时间限制，也可以加入人工审核。

### 画面安排

四个编号节点从左向右排列。用明显的回流箭头连接“检查后决定”和“选择工具”；旁边另有通往“解释与报告”的出口。模型负责的动作与程序负责的计算用不同颜色表示。

### 学生带走的一句话

**每次结果都会影响下一步，而不是只执行一串固定步骤。**

## 第 3 页｜四个角色，分工完成同一道题

### 这一页要回答什么

为什么要有多个 Agent？四个角色分别做什么？

### 屏幕文字

**主标题：像一组同学，各自负责一件事**

| 角色 | 学生能理解的职责 | 在正方形问题中的例子 |
| --- | --- | --- |
| 问题分析员 | 读懂条件与目标 | 面积为 2，求正的边长 |
| 科学求解员 | 选择方法，调用工具 | 选择求根工具，求解 x²−2=0 |
| 验证审查员 | 检查程序证据，再作复核 | 代回原式，检查差值是否足够小 |
| 报告撰写员 | 根据已有证据，解释结果 | 说明边长、计算方法与检查依据 |

反馈箭头：**检查未通过 → 返回求解员**。

底部结论：**四种角色可以共用同一个模型；分开的是职责。**

小字：验证需要程序检查通过，并且模型复核同意。

### 建议讲解稿

这四个角色就像一个分工明确的学习小组。分析员先读题，避免漏掉“边长必须为正”这样的条件。求解员选择合适的方法并调用工具。审查员先拿到程序检查的证据，再由模型复核当前步骤；程序没有通过时，模型不能把失败改成通过。报告员把已有的计算与检查记录组织成学生能读懂的说明。如果审查没通过，任务可以返回求解员继续尝试。这里的四个 Agent，并不意味着四台机器或四个不同模型；它们可以共用同一个模型，通过不同的职责设定来协作。

### 画面安排

四张等宽角色卡片，用“读题、求解、检查、讲解”作为大字。每张只有一句职责与一句例子。审查员到求解员之间增加回退箭头。原始英文名称放在演讲者备注中，不要求学生记忆。

### 演讲者术语对照

- 问题分析员：Problem Analyst。
- 科学求解员：Scientific Solver。
- 验证审查员：Verification Critic。
- 报告撰写员：Report Writer。

### 学生带走的一句话

**按职责分工，可以把求解与检查的过程讲清楚。**

## 第 4 页｜看一个例子：怎样知道结果值得相信？

### 这一页要回答什么

一个近似答案是怎样被计算和检查的？

### 屏幕文字

**主标题：算出答案以后，还要代回去检查**

问题：`x²−2 = 0，且 x > 0`。

1. **设定任务**：在 1 到 2 之间寻找正数解。
2. **工具求根**：得到 `x ≈ 1.41421356`。
3. **程序验算**：检查 `|x²−2|` 是否小于设定误差。
4. **复核与解释**：模型审阅计算证据，再组织答案。

结果卡：**边长约为 1.41421356**。

证据卡：**本例实际计算的差值约为 1.17 × 10⁻¹³，小于 10⁻⁸。**

图示：函数 `y=x²−2` 在正半轴与横轴的交点。

小字：图像用于说明交点；验算使用完整精度的工具结果。数值检查提供证据，不等于完整数学证明。

### 建议讲解稿

回到刚才的问题。边长为正，所以我们只寻找正数解。1 的平方是 1，2 的平方是 4，因此可以在 1 和 2 之间寻找答案。求根工具得到约 1.41421356。接下来不是直接宣布完成，而是用完整精度的结果代回 x²−2，看看剩下的差值是否足够接近 0。本例要求差值小于一亿分之一，实际计算得到的差值约为 1.17 乘以 10 的负 13 次方，因此这一步通过了数值检查。模型还会审阅这份证据。右边的图像帮助我们看到答案对应的交点，但图像本身不是数值精度的证明。

### 实际数值来源

本次准备过程中直接调用项目的 `backend/app/science.py` 中 `find_root`：

```text
expression = x^2-2
method = brentq
bracket = [1, 2]
tolerance = 1e-10
root = 1.4142135623731364
residual = 1.1723955140041653e-13
```

这是项目计算工具的实际输出，用于说明计算与代回检查；不把它表述成一段已经运行并保存的完整多 Agent 对话。函数图像为本 PPT 制作的数学示意图，不是产品截图。

### 画面安排

左侧为四步解题说明，右侧为清晰的函数曲线与正根标记；底部展示“近似结果”和“代回证据”。图中仅突出正数解。

### 学生带走的一句话

**既看结果，也看结果是怎样被检查的。**

## 第 5 页｜系统架构：网页背后，谁在做什么？

### 这一页要回答什么

网页、Agent、语言模型、计算工具和历史记录之间是什么关系？

### 屏幕文字

**主标题：网页展示过程，控制中心协调任务**

上层：

- **网页界面**：提问、查看结果、观察步骤、参与审核。
- **流程控制中心**：安排四个角色，传递任务与结果。

控制中心调用的三类能力：

- **语言模型**：理解问题、选择动作、审阅与解释。
- **科学计算与验算**：执行允许的数学工具，产生计算和检查证据。
- **任务记录**：保存问题、工具结果与事件历史。

图中技术名称以小字注明：

- 网页：Vue。
- 控制中心：FastAPI + LangGraph。
- 默认模型：本地 Qwen，经 vLLM 提供服务。
- 科学计算：SymPy / SciPy / NumPy。
- 记录：SQLite。

部署说明：**前端文件、后端与模型部署在内网；公网服务器只转发访问请求。**

收束句：**你提出目标，系统把理解、计算、检查和解释串起来。**

### 建议讲解稿

最后把前面的内容放回整套系统里看。学生通过网页提问，网页也会不断显示当前进度和结果。网页背后有一个流程控制中心，负责安排四个角色、执行允许的工具调用、传递结果并记录事件。语言模型帮助理解和组织动作；科学计算程序完成运算，验证逻辑提供证据；任务记录保存问题、结果和过程。四个 Agent 是这些流程中的四种职责，不是四台独立的服务器。实际部署时，前端文件、后端和模型都在内网服务器；公网只提供转发入口。学生无需记住这些技术名称，只要记住各部分的分工：界面负责呈现，控制中心负责协调，模型和计算工具各有所长。

### 画面安排

网页界面与流程控制中心置于上层，双向箭头表达“提交问题、返回进度与结果”；模型、计算与验算、任务记录置于下层，分别与控制中心相连。底部用一行小字解释内网部署与公网转发，避免将运维端口混入主图。

### 学生带走的一句话

**Agent 项目是界面、流程、模型、工具与记录的协作系统。**

## 内容核验与讲述边界

- 四角色定义：`backend/app/agents.py`；四角色可共用模型，使用不同职责与提示。
- 当前步骤的通过条件是程序检查通过且模型审阅同意，程序失败不能由模型推翻。
- 反馈循环、工具调用和重试限制：`backend/app/workflow.py`；工具参数会经注册与校验后执行。
- 示例计算：`backend/app/science.py` 的 `find_root`；代回检查对应工作流中的求根残差检查。
- 不同工具的验证强度不同，不能声称系统对所有答案完成了严格数学证明。
- 目标记录供下一轮判断，不声称它能硬性保证用户所有要求均完成。
- 当前运行中任务及人工中断包含进程内状态，不声称服务重启后所有未完成任务都能继续。
- 架构依据：项目 README、`backend/app/main.py`、`workflow.py`、`storage.py`、`llm.py` 和现有内网部署配置。
